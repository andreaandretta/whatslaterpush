⚠️ Migration richiesta in Supabase

-- Migration 0XX: enforce label palette
ALTER TABLE contact_labels
  ADD CONSTRAINT color_in_palette CHECK (
    color IN (
      '#DB4437', '#E65100', '#827717', '#0F9D58',
      '#00897B', '#1976D2', '#7E57C2', '#546E7A'
    )
  );

-- Map esistenti fuori-palette al colore più vicino
UPDATE contact_labels
  SET color = CASE
    WHEN color ~* '^#(F|E)[A-F0-9]{5}$' THEN '#E65100'  -- gialli/aranci
    WHEN color ~* '^#[0-9A-F]{2}([8-9A-F])' THEN '#1976D2'  -- chiari
    ELSE '#546E7A'  -- fallback grigio
  END
WHERE color NOT IN (
  '#DB4437', '#E65100', '#827717', '#0F9D58',
  '#00897B', '#1976D2', '#7E57C2', '#546E7A'
);

Applica manualmente in Supabase prod PRIMA di deployare la UI nuova, altrimenti la INSERT delle nuove etichette è OK ma le vecchie potrebbero violare il constraint quando vengono UPDATE.

Cosa cambia per l'utente

Impossibile creare un'etichetta illeggibile. Tap su colore = scelto, fine. Per ICP D (parroco 62enne) un click invece di scrivere un codice esadecimale.

Micro-decisioni che ho preso

  • 1. Layout 4 colonne × 2 righe invece di riga unica. Su iPhone SE (375px) 8 swatch in fila vengono 38px ciascuno = sotto tap-target 44px. 4×2 dà ~70px per swatch.
  • 2. Selezione = check-icon bianca centrale + ring-2 white. Più WA-native del classico bordo colorato e accessibile anche a chi non distingue bene i colori (daltonici, ICP D >50anni con vista ridotta).
  • 3. Niente "Custom color" come 9° opzione. Apre la possibilità di rompere il sistema. Se in futuro emerge un caso d'uso reale (es. Pro/Business pricing tier), allora forse.
  • 4. Niente nomi colore visibili nella picker UI (solo aria-label per screen reader). "Sponsor" è la label, il colore è secondario. Nomi visivi rendono il flusso più lento.

Alternative scartate

  • a. Free picker con auto-darken se contrast fail. Rompe l'aspettativa dell'utente (sceglie giallo, ottiene marrone).
  • b. 12 colori invece di 8. Paralysis-by-choice per ICP D. 8 è il punto dove copri usi reali senza overwhelm. Studio interno Google Material consiglia 5-10.
  • c. Auto-assign del colore basato sul nome label (hash → palette). Magico ma confonde: utenti diversi con stessa label vedono colori diversi.
  • d. Gruppi semantici visibili ("⚠️ Urgenti: rosso/arancio | ✓ OK: verde/teal | ..."). Troppa prescrizione. Lasciamo all'utente.
