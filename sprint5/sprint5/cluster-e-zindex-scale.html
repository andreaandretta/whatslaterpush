Cluster E · Z-index token scale

Da z-[60], z-[70], z-[80] arbitrari → scale tokenizzata

Zero impatto visivo per l'utente finale, alta riduzione di bug futuri. Un sheet aperto sopra un sheet aperto sopra l'OnboardingTour può creare layering caotico oggi.

Problemi reali oggi:
• Toast a z-50 nasconde dietro qualsiasi sheet (z-[60]).
• Onboarding (z-[80]) si stampa sopra al sheet aperto invece di guidarlo dietro.
• Se aggiungo un nuovo modal devo "indovinare" il prossimo numero libero.
Proposta — token scale semantica
Token Z Quando usarlo
z-fab 40 FAB / navbar fissi
z-modal 50 Modali base full-screen
(ContactPicker, Schedule)
z-sheet 60 Bottom sheet (Recurrence,
Template, Media, Reminder)
z-dialog 70 Dialog su un sheet aperto
(Save template, CSV import)
z-onboarding 80 Tour overlay (eccezione, regista degli altri)
z-toast 90 Toast / feedback effimero
(sempre sopra a tutto)
Logica della scala:
• Numero crescente = priorità visiva crescente.
• Buchi di 10 per inserire layer intermedi senza renumber.
• Solo eccezione: z-onboarding resta deliberatamente sotto il toast — un errore deve sempre essere visto.

tailwind.config.ts — extend zIndex

// tailwind.config.ts
export default {
  theme: {
    extend: {
      zIndex: {
        fab: '40',
        modal: '50',
        sheet: '60',
        dialog: '70',
        onboarding: '80',
        toast: '90',
      },
    },
  },
};

Tailwind genera classi z-fab, z-modal, ecc. utilizzabili direttamente nei className.

Cosa cambia per l'utente

Niente, visibilmente. Ma: errori e feedback (toast) sempre visibili anche sopra modali aperti. Per il dev: aggiungere un nuovo modal = scegliere il token semantico giusto, non indovinare un numero.

Micro-decisioni che ho preso

  • 1. z-fab = 40 (nuovo). Oggi il FAB non ha z-index esplicito → cade nello stacking context naturale. Esplicitarlo evita che un futuro absolute lo copra.
  • 2. z-toast = 90 (sopra onboarding). Inverte la regola "onboarding regista". Se Sentry/network fail durante il tour, l'errore lo vede l'utente PRIMA del tour. Sentry > Tour.
  • 3. Buchi di 10 invece di 1. Permette aggiungere z-sheet-2 = 65 in futuro (sheet sopra sheet) senza rinumerare tutto. Trade-off: stack max 9 layer — sufficiente.
  • 4. Nessun token z-popover / z-tooltip. Quei pattern non esistono nel codebase. Se servono dopo, vanno tra dialog e onboarding (75) o tra toast e tutto (95).

Alternative scartate

  • a. Scala 1, 2, 3, 4, 5. Pulito ma proibisce di inserire layer intermedi.
  • b. Scala 100, 200, 300.... Stile Material. Funziona ma rumore visivo nel CSS-dev tools (numeri grandi).
  • c. Mantenere z-50 per ContactPicker e usare token solo per i nuovi modal. Soluzione "metà incinta", mantiene il caos.
